CONFIRMED RELEASE BLOCKER: CART CANNOT REVERSE AWAY FROM A ROCK
TraversalReview.cs, final traversal.txt: excavation 4, first copper deposit intact. Player (19.20,0.03,1.91), cart attached, facing north. Four seconds of reverse input produced 0.000m escape; right input also failed. Cart overlap query was empty: this reproduced a collision deadlock, not penetration. An unchanged-facing backward sweep allowed the full 0.20m test distance.
Cause: MinerController projects velocity onto the proposed forward direction and clamps input alignment to [0,1]. Opposite input becomes zero movement while SmoothFacing attempts a turn. QuarryWheelbarrow.ConstrainMovement blocks the turn against the rock. Its backup nudge requires nonzero requested movement, so it cannot resolve this zero-motion case.
Recommended fix: allow controlled backward pulling with existing heading when turn clearance is blocked; sweep the reverse movement and keep CharacterController collision authoritative. Turn after space is gained. Preserve cargo, do not teleport or disable rock colliders. Include straight, angled, tight-corner and loaded-cart tests. Simply narrowing the cart further does not fix this logic.

All ten waypoint checks passed with foot and cart across two routes with intact copper deposits.
Inside ridge: centre aisle x=20.45 from z=9.4 to z=2.2, through south entrance to z=-3.8, then west to x=12 before returning toward refinery.
Outside west ridge: corridor x=16.7 from z=8 south to z=-3.8, then west to x=12.
Actual end positions were within 0.25m foot / 0.20m cart of targets.
Unlocked-ridge NavMesh query returned PathComplete from (20.45,.05,9.4) to refinery input (3.1,0,0). A closed-gate query was partial as expected.
Navigation is built for radius .5m; player radius .3m. Cart sits .95m ahead with .55m half-length. A circular navigation agent does not validate the cart's turning sweep.
Recommendation: visibly marked continuous return lane, generous turn pockets, junction arrows toward REFINERY / MAIN QUARRY, optional return destination even with empty cart. Guide currently replaces mine goals with PARK TO USE PICKAXE and targets the player when pushing, which is unhelpful for finding the exit. Avoid opening the outer world boundary; create readable connected passages inside the play area.

VISUAL / ANIMATION
cart-rock-reverse.png confirms oversized Copper Ridge world-space text covers the view near the entrance. Use a smaller mounted sign and sensible viewing distance.
Current implementation uses DitzelGames.FastIK.FastIKFabric, not Final IK. MinerAnimator corrects right-hand carry and QuarryWheelbarrow manually solves both wrists while pushing. Current Animator clips contain idle/locomotion/jump/fall/mining, but no dedicated push/pull or pickup clips.
Recommendation: authored idle, walk/run, ground/wall mining, brief pickup/put-down and cart push/pull/idle clips, tool sockets parented to hands, animation-timed contact. Keep ore collection responsive: do not interrupt movement with a full pickup animation for every item. Optional small hand correction only where necessary; do not use IK to substitute for the entire pushing pose. Removing IK alone without replacement poses will not improve hand contact.
